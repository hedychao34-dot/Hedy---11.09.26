# 製程文件雙語同步助理｜OpenSpec 作業起步

## 放置位置與本次停點

將此檔放在原型專案的 `docs/OpenSpec_作業起步.md`，`docs/` 與該專案的 `openspec/` 同層。在 VS Code 開啟這個專案根資料夾。原始 PRD／Spec 摘要可選擇放進同一個 `docs/` 供參考。

本次只提出 V1 規格，完成後停止並等我確認。V1 實作、歸檔與 V2 各由我另行下達指令。下方兩版表格是交件順序。

## Prototype 的第一個任務

製程文件負責人以一份虛構 PCP 表格示範繁中轉美式英文。Prototype 套用既有核准譯文，顯示一筆待確認的譯文候選，讓使用者修改或確認，再產出英文預覽。這是供課堂展示的第一版切片，原提案的 MVP 仍涵蓋 PCP、PFD、PFMEA 各一套固定範本。

- 資料可由 Codex 生成。若做畫面原型，內建虛構 PCP 資料即可。若規格納入實際 Excel 匯入，再生成可上傳測試的虛構 `.xlsx`。若採預設候選，畫面標示模擬資料。
- V1 驗收：核准譯文與候選能辨別，使用者能處理候選，英文預覽反映確認結果。
- 第一版的 Excel 檔案匯入／匯出與是否使用真正的翻譯模型，由提案階段確認。若做模擬，展示及 PPT 應說明實際範圍。
- 不處理正式文件、改版同步或自動核准發行。原提案的公司內部資料處理要求繼續適用於日後的正式使用。

## 兩版迭代與交件

| 階段 | 產出與驗收 |
|---|---|
| V1 提案與實作 | 以現有提案作背景，先產出 OpenSpec 的 proposal、design、specs、tasks，確認範圍後實作及試走。保留 V1 畫面、試走紀錄、歸檔與 Git 版本。 |
| V2 提案與實作 | V1 驗收後，根據自己實際試走的紀錄或同學回饋挑一個問題，再由我另行要求開一筆 OpenSpec change。自測如實標「原型自測」，不當成問卷或目標客戶驗證。驗收後保存前後對照、歸檔與 Git 版本。 |
| GitHub 與 PPT | Repository 放程式碼、執行方式、虛構資料及兩版 OpenSpec 紀錄。PPT 呈現問題、V1 流程、觀察、V2 變更、驗收與 GitHub 連結。若老師要求公開試用網址，另外確認部署方式。 |

## 給 Codex 的第一句

在原型專案初始化 OpenSpec 後，貼上以下文字，將第一版停在可審查的規格。

> $openspec-propose 請先讀 `docs/OpenSpec_作業起步.md`，只提出製程文件雙語同步助理 Prototype V1。以一份虛構 PCP 示範核准譯文套用、候選確認與英文結果預覽。請在 proposal、design、specs、tasks 寫清楚展示方式、哪些部分是模擬、Excel 匯入／匯出是否納入，以及逐步驗收條件。規格完成後停止，等我確認。這次不實作、不歸檔、不建立或執行 V2。

原始需求可搭配《PRD_Spec_依賴_Review_Roadmap_交付摘要.md》。本頁的 V1 展示切片是建議，V2 尚無回饋或驗收結果。
